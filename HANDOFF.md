# Sand & Bone — состояние на 2026-07-31

Тактический трекер для Warhammer AoS: Spearhead. Один файл `index.html`
(2460 строк, без сборки), данные в `armies.json`, комната/синк через Firebase
(`firebase-room.js`, свой проект `spearhead-tracker`). Деплой — GitHub Pages,
репо `romanfilin-design/Spearhead-generator`, автодеплой на push в `main`.

Последний коммит (`93b228d`) задеплоен успешно.

## Визуальный язык — откуда он взят

Дизайн **дословно** взят из мокапа `design-concepts/v2/layout-2c-ember-red.html`
("Command Deck", Ember Red палитра). Токены в `:root` — буквально значения
из мокапа (`--void #0C0B0A`, `--panel #17140F`, `--bronze-src #C25538` и т.д.),
плюс алиасы под старые имена переменных (`--ember`, `--surf-*`, `--ink*`) —
не трогать без причины, весь файл держится на этой системе.

**Если правишь визуал — сначала смотри на мокап, а не на то, что "было в проде
раньше".** В этом чате несколько раз пришлось откатывать патчи "поверх старого"
и делать 1:1 перенос — экономит время делать так сразу.

## Структура приложения (после сегодняшних правок)

- `#modePicker` — экран выбора режима (poster-stack, только "Sand & Bone" активен).
- `#appBody` → `.tabbar` (**теперь sticky top**, не fixed-bottom) → `.wrap` →
  4 `.tabpanel`: `tab-prep` (Подготовка) / `tab-twist` (Твист) / `tab-army`
  (Армия) / `tab-hand` (Тактики). Переключение — `switchTab(name)`.
- **Чип "Режим: X / Сменить"** живёт теперь ТОЛЬКО внутри `tab-prep`
  (`#modePickerSelected`), не виден на других табах.
- **`.armybar`** — новый компактный однострочный блок (раунд ‹›, ВП И1/И2 −/+,
  тег "ничья"), верх таба **Армия**. Обновляется через `refreshHeroChips()`,
  которая теперь пишет в `[data-roundnum]` и `[data-vp="p1"/"p2"]` (плюс
  старые `[data-roundchip]`/`[data-vpchip]` — те ещё живы на табах
  Твист/Тактики через `.tabchips`, не убирал).
- **Карточки юнитов (`renderUnitCard`) больше не показывают раунд/ВП** —
  `.herotopbar` полностью убран из `renderUnitCard`, CSS-правило `.herotopbar`
  удалено как мёртвое.
- Портреты юнитов: `.herowrap` высота **400px** (было 300 — по просьбе
  показывать больше картинки, меньше кропа). Источники — `.webp` в
  `assets/textures/*_nobg.webp` (сконвертированы из PNG, `armies.json`
  ссылается на `.webp`; старые `.png` остались в репо неиспользуемыми,
  не удалял без спроса).

- `.iconbtn` (M/S/C/X) — теперь `<button>` с `aria-pressed`, не `<div onclick>`.
- Заголовки юнитов подняты до `<h3>` (были голый `<div>`/`<h4>`, пропуск уровня).

- HP-бар: `transition: width` → `transform: scaleX()` (детектор ловил
  layout-thrash на `width`).
- Портреты юнитов: PNG → WebP (8.9MB → 1.6MB суммарно по используемым файлам).
- Таблица оружия на мобильных: было `table-layout:fixed` с равными долями

  классы `.wname/.wrange/.wstat/.wability` с процентными ширинами — имена

- Тексты кнопок: "Отметить использованной" → "Использовать",
  "Отметить Reinforcements" → "Reinforcement".

## Известные компромиссы (осознанно, не баги)

- `.term-clickable` (тултипы терминов оружия в таблице) — увеличенная зона
  тапа через padding+отрицательный margin, но НЕ полные 44px: в плотной
  таблице физически не влезает без разрушения плотности.
- Desktop-раскладка — та же колонка `.wrap{max-width:680px}`, что и на
  мобильном, просто по центру широкого экрана. Не делал отдельную
  desktop-раскладку — по PRODUCT.md десктоп вторичен, это было явно
  low-priority в аудите.
- `prefers-reduced-motion` больше не убивает переход цвета HP-бара
  (steel→amber→red) — это смысловой сигнал "юнит умирает", не декор,
  специально исключил из общего "убийцы" анимаций.

## Технические грабли, на которые не наступать снова

1. **`aspect-ratio` + `flex:1` + `min-height` в одном правиле** — на узких
   экранах aspect-ratio не даёт сжаться до min-height, ряд элементов
   переполняет контейнер. Управлять высотой через padding, не aspect-ratio,
   если элемент внутри flex-row с непредсказуемой шириной.
2. **`class="wname"` одновременно на `<th>` и `<td>`** — если у класса есть
   правило `color:...;font-weight:600` под общим селектором `table.wtable
   .wname`, оно перекрывает стиль заголовка (`table.wtable th`) по
   специфичности. Разделять правила на `td.wname`/`th.wname` явно.
3. **Скролл/скриншот в браузерном инструменте этой сессии периодически
   "залипал"** на старой позиции/кадре — если скриншот не совпадает с тем,
   что должно быть, перепроверяй через `getBoundingClientRect()`/computed
   style напрямую, а не доверяй один скриншот.
4. **`fetch('armies.json',{cache:'no-store'})` в новой вкладке иногда
   возвращал старое содержимое** сразу после правки файла — если данные не
   обновились визуально, вызови `loadArmies()` вручную через JS-консоль,
   прежде чем считать это багом кода.
