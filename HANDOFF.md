# Sand & Bone — состояние на 2026-07-31 (конец сессии)

Тактический трекер для Warhammer AoS: Spearhead. Один файл `index.html`
(без сборки), данные в `armies.json`, комната/синк через Firebase
(`firebase-room.js`, свой проект `spearhead-tracker`). Деплой — GitHub Pages,
репо `romanfilin-design/Spearhead-generator`, автодеплой на push в `main`.

Последний коммит (`29b321a`) задеплоен успешно. Пользователь сказал, что

Дизайн взят из мокапа `design-concepts/v2/layout-2c-ember-red.html`

## Структура приложения

- `#modePicker` — экран выбора режима. `chooseMode()`/`changeMode()`
  прячут/показывают **весь** `#modePicker` целиком (не только
  `#modePickerGrid`) — раньше контейнер оставался в DOM с паддингом,
  создавая зазор над таббаром.
- `#appBody` → `.wrap` (max-width 680px) → 4 `.tabpanel`: `tab-prep`
  (Подготовка) / `tab-twist` (Твист) / `tab-army` (Армия) / `tab-hand`
  (Тактики). Переключение — `switchTab(name)`.
- **`.tabbar` — снизу экрана** (`position:fixed;bottom:0`, было сверху).
  `.wrap` получил `padding-bottom: calc(70px + env(safe-area-inset-bottom))`,
  чтобы контент не прятался под баром. Ряд кнопок обёрнут в
  `.tabbar-row` (max-width 680px, центрирован) — сам `.tabbar` фон/бордер
  на всю ширину, чтобы не отрывался от колонки на широких экранах.
- **`.armybar`** — единый виджет раунда/ВП/тега "ничья", **одинаковый на
  всех 4 табах** (было 3 разные реализации + отсутствие на Подготовке).
  `justify-content:center` — центрирован на любой ширине. `flex-wrap:wrap`
  — при нехватке места первым переносится тег "ничья" (наименее важный),
  подписи И1/И2 никогда не скрываются (раньше пропадали <360px).
  Обновляется через `refreshHeroChips()` (пишет в `[data-roundnum]`,
  `[data-vp="p1"/"p2"]`, `.underdogtag` — единственный класс, `id` убран).
- **Кнопки сброса** ("Новый ход: сбросить «раз за ход»", "Сбросить
  армию") — статичная разметка сразу под `.armybar` на табе Армия (было
  внизу, после всего ростера). `.turnresetrow button { flex:1 }` —
  всегда в одну строку, текст переносится внутри кнопки, а не сами
  кнопки на разные строки.
- **"Комната"** (`.bottomsheet`) — стилизована как `.card` (surf-1 фон,
  полная рамка, padding 18px), а не full-bleed полоса. `.roomrow`
  центрирован.

## Карточка юнита (`renderUnitCard`)

- Портрет **наверху**, во всю ширину карточки (`.herowrap`, 400px,
  `background-size: contain` — юнит показан целиком, без кропа/зума).
  Имя + ключевые слова наложены снизу (`.herobottom`), buff-пилюли
  (`buffPillsFor`) — сверху справа.
- **Сворачивание вернули** (было убрано, потом по просьбе пользователя
  восстановлено в другом виде): кнопка-тоггл `.cardtoggle-btn` (40×40,
  круг) сидит **поверх портрета**, top-left угол. По умолчанию **всё
  развёрнуто**. Сворачивает только стат-блок/оружие/способности/лор —
  портрет, имя, HP-бар и M/S/C/X всегда видны независимо от состояния.
  Состояние — `unitCardOpen{}` (JS-объект, НЕ синхронизируется/не
  персистится, сбрасывается на reload; отсутствие ключа или `true` =
  открыто, только явный `false` = свёрнуто).
- **Левая акцентная полоска** (`.unitcard::before`, бронза/ember) — нужен
  `z-index:1`, иначе `.herowrap` (bleeds к краю через отрицательный
  margin) перекрывает её визуально. Если добавляешь что-то ещё поверх
  портрета — помни про эту стопку.
- Генерал в ростере — `.unitroster li.general` (★ + бронзовый текст,
  раньше просто bold-префикс).
- Выбранная способность отряда/улучшение генерала — компактная
  `<details class="accordion">` строка (имя + шеврон), а не полная
  карточка веса боевой черты. Плейсхолдер "ещё не выбрана" — остаётся
  полным блоком (`.choiceblock`/`.cb-empty`).
- Toast-undo (4.5с, кнопка "Отменить") — теперь **и** на `resetArmy()`,
  и на `resetTurnFlags()`, не только на HP/VP.

## Технические грабли, на которые не наступать снова

1. **`aspect-ratio` + `flex:1` + `min-height`** в одном правиле — на
   узких экранах не даёт сжаться, переполняет контейнер. Управлять
   высотой через padding.
2. **Один класс на `<th>` и `<td>`** — специфичность ломает стиль
   заголовка. Разделять `td.x`/`th.x` явно.
3. **`html { scroll-behavior: smooth }` — глобальный** (не мой код,
   был всегда). Любой программный `scrollTo` должен передавать явный
   `{behavior:'auto'}`, иначе вместо мгновенного прыжка получится
   анимация "проехать" через весь предыдущий скролл — актуально для
   `switchTab()`, который обязан сбрасывать скролл мгновенно.
4. **`fetch('armies.json',{cache:'no-store'})`** иногда отдаёт старое
   содержимое в новой вкладке сразу после правки файла — звать
   `loadArmies()` вручную через консоль, прежде чем считать багом кода.
5. **Скролл/скриншот в браузерном инструменте этой сессии периодически
   "залипает"** на старом кадре, а `computer.scroll` с жестом мыши может
   зависать (таймаут 30с) в этом окружении — не доверяй одному
   скриншоту, перепроверяй через `getBoundingClientRect()`/computed
   style/`window.scrollY` напрямую через JS.
6. **Z-index стопка над `.herowrap`**: портрет юнита рендерится через
   `background-image` на полнобитном (bleeds to edges) блоке —
   элементы, которые должны быть видны поверх портрета (акцентная
   полоска карточки, кнопка сворачивания), нуждаются в явном
   `z-index` выше `auto`, иначе фото их перекрывает.

## Известные компромиссы (осознанно, не баги)

- Desktop — та же колонка `.wrap{max-width:680px}`, просто по центру.
  Не делал отдельную desktop-раскладку — по PRODUCT.md low-priority.
- `prefers-reduced-motion` не убивает переход цвета HP-бара
  (steel→amber→red) — смысловой сигнал "юнит умирает", не декор.
- `.term-clickable` (тултипы терминов оружия) — увеличенная зона тапа
  через padding, но не полные 44px — в плотной таблице не влезает.
